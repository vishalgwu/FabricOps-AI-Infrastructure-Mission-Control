# FabricOps Evaluation Report

Dataset version **1**, **29 cases**. Generated by `python -m evals --write-report`; a test fails if this file is out of date.

## Read this first

- **This measures the safeguards around the model, not the model.** Every case scripts what the model does (one good answer, or one specific kind of bad answer) and checks that the *system* behaves correctly: it abstains on bad data, refuses invented IDs, blocks out-of-scope proposals, classifies risk itself, and holds risky proposals for a human.
- **No real model was used.** Nothing here says how good Claude's hypotheses are. Claim support (are the claims actually supported by the evidence?) needs a person; see [the rubric](CLAIM_SUPPORT_RUBRIC.md). **No manual claim-support review has been done yet.**
- **The sample is tiny and synthetic**: one fixture per scenario and a handful of cases per failure type. The numbers below are counts out of small totals. They are not statistically meaningful and are not an accuracy estimate. A result of 5/5 means "every case written passed", not "5 out of 5 would pass in general".
- **The cases were written alongside the safeguards they test**, so they cover what was thought of. Cases nobody thought of are not covered.
- **Latency and token cost are not reported.** With a scripted model they are meaningless. The optional live smoke test (`python -m evals.live`, needs an API key) records them; it has not been run.

- *Cited IDs that resolve to stored records*: Counts existence only, not whether a passage supports the claim (see claim support).

## Known gaps (things the system does not catch)

- **E27, Model cites an irrelevant document that WAS retrieved.** The system checks that a cited passage exists and was retrieved for this run, not that it is relevant to the claim. An irrelevant but retrieved passage is accepted. Catching this needs the manual claim-support review.

## What is not covered

- Real model behaviour: hallucination rate, how often it abstains when it should, quality of its next-step suggestions.
- Whether cited documents genuinely support the claims they are attached to.
- Real telemetry: the data is fabricated, clean and small, so noisy or very large inputs are untested.
- Load, concurrency beyond a few threads, and a server crash during a run (Phase 11).
- Anything about the UI beyond its own tests (see the frontend test suite).
